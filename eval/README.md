# 对比实验

这个目录是离线的对比实验：用同一批命题要求跑不同的出题流程配置，比较交付率、答案正确率、调用次数、Token、用时和费用，看每个环节值不值得保留。它不属于 Tetra 的产品功能，界面里没有入口，README 和 `docs/` 也不介绍它。

| 文件 | 内容 |
|---|---|
| `ablation.py` | 按各种配置出题 |
| `judge.py` | 评判出成的题 |
| `report.py` | 汇总出表和图，抽题给人工核对 |
| `common.py` | 共用部分 |
| `results/` | 实验结果，按测试集分目录 |

## 设计

- **基线**：Z 直接提问。把同一条出题要求原样发给同一个模型（同样开思考），只规定按 JSON 返回题干、选项、答案和解析，相当于直接在对话框里让大模型出题。
- **结构对比**：A 只有命题员 → B 加审题员 → C 加解题员、复核员（完整闭环，就是界面上默认的出题方式）→ D 再加验算员。
- **机制对比**：在 C 上每次关掉一个机制，即思考模式、先构造后成题、答案闸门、关键结果共享、审题答案交叉核对、定点修改（`C-reroll`：退回后整份重写，到上限算失败）。开关在 `mingti/question_authoring/providers.py` 的 `PipelineSwitches` 里，默认全开，和界面出题一样。用 `--configs C-gate,C-xcheck` 选择要跑的配置。
- **测试集**：从 `data/blueprint_specs.json` 按题型和难度分层抽题。`pilot` 10 道，`small` 30 道（4、5 星 16 道），`full` 60 道；小的集合都包含在大的里。
- **判分**：评判模型只看题面独立解 3 次，多数表决判答案对错，同时看考点和难度是否符合要求。评判默认用 `deepseek-flash`；它和出题是同一个模型时可能犯同样的错，所以另抽题目人工核对，报告两者的一致率。人工核对是盲审：看题的表里没有配置名称和评判结论，顺序打乱。
- **版本**：每条结果记下 git 提交号和提示词版本；出题流程、实验脚本或测试集有没提交的改动时，提交号后面带 `-dirty`。正式跑之前先提交，跑的过程中不改出题流程。

## 运行

在项目目录下运行（出题和评判用项目的 `.venv`，汇总用装了 matplotlib 的 Python）：

```bash
.venv\Scripts\python eval\ablation.py small --budget 3
.venv\Scripts\python eval\judge.py small
python eval\report.py small --audit 30
```

`small` 默认跑 7 种配置：Z、A、B、C、D、C 关思考模式、C 关先构造后成题，共 210 次出题。依次是出题、评判出成的题、汇总出表和图，并抽 30 道题给人工核对：`human_audit.md` 看题，结论填进 `human_audit.csv`；每个编号对应哪次出题、评判怎么判的在 `human_audit_key.csv`，填完再看。再运行一次 `report.py` 就会算出一致率。已经填了结论时 `--audit` 不会覆盖，确实要重抽加 `--audit-force`。

- `--budget 3` 表示花到 3 美元（按闲时价算）就不再开始新的出题。
- 结果都在 `eval/results/`，不写应用自己的命题记录和题库。
- 中途停了（包括模型账户余额不足、返回 HTTP 402 时脚本自己停下），再运行同一条命令会接着跑没完成的。
- 实验脚本的 API Key 读的是 `.env`，不是界面里配置的模型服务。
